Mount errors, no files visible, frequent disconnects? Locate and fix Synology cloud drive mounting problems step by step, organized by symptom.

1. Common Mount Failure Symptoms at a Glance

Mounting problems look varied but usually fall into the categories below. Matching the symptom first helps you find the right direction faster.

SymptomCommon causeCheck first
Login or authentication failureInvalid password or expired QR login, drive-side restrictionAccount and network
Mounts but the directory is emptyWrong mount point, insufficient permission, empty cloud directoryMount point and permissions
Frequent disconnects after mountingNetwork fluctuation, expired authorization, firewall blockingNetwork and firewall
Package fails to start or reports errorsPackage exception, encrypted folder not unlockedPackage and system settings

2. Step 1: Confirm the Basic Environment

Most "cannot mount" problems come down to the three most basic things. Confirm each one first:

  • The NAS is powered on and reachable: you can log into DSM or access it through the web interface normally
  • The network connection is stable: the NAS network works and can reach the target drive service
  • The account information is correct: the password or QR login state is valid and there is no abnormal login restriction on the drive side
  • The package is installed and running: the mount package is started, not stopped or disabled

3. Step 2: Check Permissions and Firewall

If the basic environment is fine, focus on permissions and network policy. Mounting essentially makes the NAS access a remote resource, so blocked permissions or ports will always fail.

  • Shared folder permissions: confirm the account used has read/write permission on the target shared folder
  • Access permissions: confirm the account has sufficient access to the remote directory to mount; insufficient permission leads to a mount that succeeds but cannot read or write
  • Firewall settings: check whether the Synology firewall or the router blocks the ports needed for the connection; when using protocols such as NFS or SMB, not opening the corresponding ports also causes mount failures
  • Protocol version: some older devices need an adjusted protocol version (for example NFS vers=2/3/4) to mount successfully

4. Step 3: Mounted but No Files Visible

"It shows as mounted but the directory is empty" is the most common confusion. Check in order:

  1. Refresh the File Station interface, or exit the mount directory and re-enter it
  2. Verify the mount point targets the correct cloud directory (many drives mount the root or a specific folder by default)
  3. Confirm the cloud directory itself is not empty, or that resources have not finished syncing
  4. Sign out of the account and sign in again to refresh the authorization, then re-mount
Tip: If only one drive shows no files while others work normally, it is most likely an authorization or directory setting issue with that drive, not the NAS itself.

5. Step 4: Frequent Disconnects

Mounting connects but drops after a while, usually related to connection stability:

  • Network fluctuation: confirm the NAS network is stable and avoid weak Wi-Fi signals or frequent router restarts
  • Expired authorization: after the drive login token expires, sign in again to refresh it
  • Blocked ports: check whether security software, a proxy or a firewall is interrupting the connection
  • Too many simultaneous mounts: mounting too many drives at once can worsen resource contention, so reduce concurrency first and observe

6. Step 5: Uninstall, Reinstall and Full Reset

If the checks above still leave problems, reset from lightest to heaviest:

  1. Unmount the current mount point and mount it again
  2. Sign out of the account and sign in again to refresh all authorizations
  3. Stop and restart the mount package
  4. If necessary, uninstall the package and reinstall it (see the Synology package install tutorial); the configuration will be re-initialized
  5. If an encrypted shared folder is involved, sign in as an administrator, select it under Control Panel > Shared Folder and click Mount to unlock it, then retry

7. FAQ

Q: Why can't I see files after mounting a cloud drive on Synology?

A: First refresh File Station or re-enter the mount directory. If it is still empty, check that the mount point is set correctly and the account still has permission, then sign out, sign back in and mount again. In some cases the cloud directory itself is empty or has not finished syncing.

Q: Why does my Synology cloud drive mount keep disconnecting?

A: Common causes are unstable networking, an expired account login token or firewall blocking. Confirm the network is stable and the router is not blocking the ports, then sign in again to refresh the authorization. If disconnects persist, check whether security software or a proxy is interfering.

Q: What should I do if mounting fails with a login or authentication error?

A: First confirm the account password or QR login is still valid and there is no abnormal login restriction on the drive side. Then confirm the NAS network can reach the drive service. If it keeps failing, sign out, sign back in and mount again.

Q: Does an encrypted shared folder affect mounting?

A: Yes. If the target shared folder is encrypted and not mounted (unlocked), related tasks may fail. Sign in as an administrator, select the encrypted folder under Control Panel > Shared Folder and click Mount to unlock it, then retry.
